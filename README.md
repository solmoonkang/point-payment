# point-payment

제로페이 스포츠상품권(튼튼머니 포인트)으로 킵페이 보험을 결제하는 흐름을 로컬에서 한 바퀴 돌려 보는 프로젝트다.
화면 그림과 시나리오는 `~/Downloads/261014 KSPO 튼튼머니 스포츠상품권 결제 - 시나리오.html` 이 기준이다.

## 실행

```bash
pnpm install
pnpm dev        # 킵페이(5200) · 제로페이 모의(5100) 를 함께 띄움
```

| 누가 | 주소 | 계정 |
|---|---|---|
| 회원 (제로페이 시작 화면) | http://localhost:5100/ | hong / 1234 · kim / 1234 (결제 비밀번호 123456) |
| 회원 (킵페이 보험 가입) | http://localhost:5200/ | 제로페이 링크로 넘어옴 |
| 킵페이 운영자 | http://localhost:5200/admin | admin / admin1234 |
| 제로페이 운영자 | http://localhost:5100/admin | admin / admin1234 |

킵페이를 5000 이 아닌 5200 에 띄우는 이유: macOS 의 AirPlay 수신(ControlCenter)이 5000 을 쓴다.

## 한 바퀴

1. 제로페이 운영자 → 상품권 지급: 회원에게 35,000P (튼튼머니를 상품권으로 바꿔 둔 상태)
2. 회원 → 제로페이 로그인 → 「킵페이에서 가입하기」 (일회용 값을 붙여 킵페이 예시 1 로 이동)
3. 킵페이 → 보험 선택 · 약관 동의 · 고객정보(킵페이 가입) · 헬스장 · 결제
4. 제로페이 결제 승인 화면 → 결제 비밀번호 → 킵페이 결제 결과
5. 킵페이 운영자 → 가입자 리스트 · 가입 취소 / 제로페이 운영자 → 상품권 내역

포인트가 모자라면 상품권으로 낼 수 있는 만큼 내고 나머지는 카드(PG 흉내)로 낸다.

## 실패 경우 확인

| 경우 | 켜는 곳 | 기대 결과 |
|---|---|---|
| 사용 요청 응답 없음 | 제로페이 운영자 → 오류 상황 설정 | 킵페이가 같은 요청 번호로 다시 보내 한 번만 차감 |
| 사용 취소 실패 | 제로페이 운영자 → 오류 상황 설정 | 킵페이 주문이 「취소 미완료」, 다시 취소하면 복원 |
| PG 결제 실패 | 킵페이 운영자 → 개발용 설정 | 승인된 상품권을 복원하고 결제 실패 |

## 구성

```
apps/keepay        킵페이 서버 + 화면 (나중에 실제 킵페이로 옮길 코드)
apps/zeropay       제로페이 모의 서버 + 화면 (실제 연동이 열리면 지운다, 화면에는 「제로페이 모의」 표기)
packages/contract  두 서버 사이 연동 계약 (zod)
contracts/v0.md    같은 연동 규격을 사람이 읽는 문서
```

## 검사

```bash
pnpm check   # 타입 검사 (서버 · 화면)
pnpm test    # 단위 테스트 (계약 · 제로페이 상품권 · 킵페이 결제)
```

## 넣지 않은 것

- 실제 제로페이 · 쿠콘 · PG 연동, 본인인증
- 부분 취소, 매달 결제, 할인 쿠폰, 지급 건별 만료
- 저장소는 메모리라 서버를 다시 켜면 처음 상태로 돌아간다
